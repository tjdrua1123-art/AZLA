# FPS 모드 비율 조정 — 2026-11-11

사용자가 제공한 이미지의 설정을 참고했습니다. 이미지에 적힌 프로게이머 관련 설명은 별도로 확인한 출처가 아니며, 특정 선수의 공식 설정이나 보편적인 발소리 최적값으로 주장하지 않습니다.

요청은 원본 값을 그대로 적용하는 것이 아니라 **강조 비율을 유지하면서 앱의 클리핑 안내가 뜨지 않는 최대 수준**으로 조정하는 것입니다. 다른 모드와 경고 기준은 그대로 유지합니다.

| 주파수 Hz | 이미지 게인 dB | FPS 적용 dB |
|---|---:|---:|
| 31 | 0 | 0 |
| 62 | 0 | 0 |
| 125 | 6 | 2.8 |
| 250 | 3.5 | 1.6 |
| 500 | 10 | 4.6 |
| 1000 | 9 | 4.2 |
| 2000 | 7 | 3.3 |
| 4000 | 8 | 3.7 |
| 8000 | 9 | 4.2 |
| 16000 | 미기재 | 0 |

모든 필터는 PEAK, Q 1.4입니다. 원본 게인에 공통 배율 **0.4649**를 곱하고 UI와 같은 0.1 dB 단위로 반올림했습니다. 반올림 때문에 밴드 사이 비율에 최대 0.05 dB의 차이가 생깁니다. 기존 FPS의 6 kHz 밴드는 이미지의 8 kHz로 바꿨고, 31·62 Hz도 이미지대로 맞췄습니다.

원본 게인을 현재 PEAK·Q 1.4로 계산하면 합성 최대는 약 +13.08 dB입니다. 배율을 이분 탐색하고 수정하지 않은 제조사 SDK의 96 kHz 정수 계수로 검증했습니다. 20 Hz–20 kHz의 65,537개 지점에서 최종 응답과 순차 누적 필터 응답을 모두 확인했습니다.

- 적용값의 최대 합성·누적 응답: 약 **+5.96 dB**
- 공통 배율의 다음 반올림 단계(약 0.4650, 500 Hz +4.7 dB): 최대 약 **+6.06 dB**
- 앱의 기존 안내 조건: 예상 최대 **+6 dB 초과**

즉 0.1 dB 단위와 공통 배율 조건에서 다음 단계는 안내 기준을 넘으므로 현재 값을 사용합니다. 앱 경고 기준은 실제 하드웨어의 클리핑 한계가 아닙니다. 양의 EQ 게인이 있으므로 입력 신호·DAC·음량에 따라 실제 클리핑이 발생할 수 있으며, 볼륨은 낮게 시작해야 합니다. 실제 청음·측정은 수행하지 않았습니다.

재현: `npm test`, `node scripts/analyze-presets.mjs`, `python tests/browser_smoke.py`. 세부 소프트웨어 결과는 `preset-response-audit.json`, 응답 곡선 데이터는 `preset-response-curves.csv`입니다. 이전에 저장한 사용자 EQ 기록은 변경하지 않습니다.
