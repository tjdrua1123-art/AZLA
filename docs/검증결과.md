# AZLA Equalizer 2.0 검증 기록

## 원본 SDK와 수정

사용자의 최신 GitHub main에서 원본 SDK를 확인해 수정 없이 포함했습니다.

- 파일: `sdk/walk-play-web-eq-sdk.umd.js`, 94,147바이트
- SHA-256: `9a096081ab1f48e295ddb0f8dcca45bfa629082cacacf550d1af848559d4e579`
- 전역: `WalkPlayWebEqSDK`, 경로: `CB`, Report ID: `75`
- EQ: 36바이트 × 10개, 밴드 0~9
- RAM: `[1,10,4,0,0,255,255]`, 7바이트
- Flash: `[1,1,0]`, **3바이트**

이전 검토 코드가 Flash도 7바이트로 가정해 실제 명령을 거부하던 오류를 수정했습니다. 원본 `setEqInfo()`와 직접 `refereshToFlash()`는 명령을 동기적으로 생성합니다. 앱은 이를 사전 확인하고 실제 HID로 순차 전송하며 130ms 간격과 Flash 전 1,100ms 대기를 유지합니다. 타이머가 있는 SDK `saveEqInfo()` shortcut은 사용하지 않습니다.

빈 장치 목록으로 연결을 막던 설정을 바꾸어 기본 `manufacturer` 모드에서 기존 10개 VID 검색과 사용자 선택을 사용합니다. 출력 Report 75를 확인하며 정확한 VID/PID 제한의 `registered` 모드도 지원합니다.

## 수행 결과

**소프트웨어 검증 43개 통과: 기본 검증 32개 + 원본 SDK 통합 11개.**

- EQ/DSP 11개: 기본 사운드, 단일 PEAK, 합성 응답, pass·shelf, 유효성, 사운드 설정 독립성, REW 파싱·보간·비교.
- 전송 모의 검증 14개: 12개 저장 명령 순서·대기, 잘못된 입력·장치·패킷 차단, 중복 실행, USB 오류·분리·타임아웃, 42회 저장·로그 순환, 계수 해석, 정보 검색, 읽기 전용 EQ Tag 요청·응답과 타임아웃.
- 저장 상태 7개: 매 실행 기본 사운드·Q 0.75, v5에서 EQ·이름 미저장, v1~v4 사용자 저장 키 실제 삭제, 저장소 오류 시 안전한 기본 사운드 복구, 성공한 Flash 전송값의 별도 기록과 손상 기록 차단.
- **수정하지 않은 제조사 SDK + 모의 HID 11개**: 원본 해시·API, 10개 0dB 밴드, 정확한 RAM·3바이트 Flash, 96kHz PEAK 중심 응답, 7개 모드, 정수 계수 해석, 전송·대기, 35회 저장·로그 순환, 제조사 검색과 잘못된 VID/인터페이스 차단.

Chromium에서 7개 모드와 새 중심 대역, 수동 편집·되돌리기, Q 입력, 기존 사용자 저장 삭제, 재실행 기본 사운드, REW 비교를 확인했습니다. 원본 SDK + 모의 HID로 실제 Tag 읽기 요청, 현재 상태의 마지막 Flash 전송값 대조, 10개 EQ, RAM, Flash 명령과 편집 중 자동 쓰기 없음도 통과했습니다. 대비를 높인 화이트·실버의 1920×1080·1366×768 기본/세부 화면과 390px 모바일 화면은 `docs/screenshots/azla-light-*.png`에 기록했습니다.

## 계수와 필터

SDK int32 LE 계수는 7번 바이트부터 해석합니다. 일반 필터는 `2³⁰`, HIGH SHELF는 `2²⁷`이며 피드백 부호를 표준 biquad 분모로 변환합니다. PEAK의 ±6dB 중심 응답이 소프트웨어에서 설정값과 일치했습니다. 96kHz는 SDK 계산 기준으로 실제 DSP 실행 레이트 확인을 대신하지 않습니다.

LOW SHELF는 Q를 쓰지 않고 slope 0.8을 사용합니다. HIGH SHELF는 SDK에서 절댓값 게인·계수 제한·0.85 headroom 보정을 사용합니다. 이 내용은 코드 분석 결과이며 실제 출력 검증을 대신하지 않습니다. SDK는 수정하지 않았고 7개 기본 모드는 Q 0.75의 PEAK만 사용합니다.

## 실제 장치·배포의 한계

사용자는 기존 프로그램의 실제 Flash 저장 성공을 확인했습니다. 이번 환경에는 실제 DAC가 없어 **새 버전의 실제 통신·음향 변화·전원 차단 후 Flash 보존은 검증하지 않았습니다.** 모의 HID가 실제 USB나 펌웨어 동작을 증명하지 않습니다. 완료 표시는 Flash 저장 명령 전송 완료입니다.

현재 상태 기능이 기기에서 직접 읽는 값은 `[128,9,0]` 요청에 대한 **Tag ID**입니다. 제조사 SDK에는 Flash의 10밴드 전체를 역으로 읽는 API가 없습니다. 화면의 상세 값은 기기 VID/PID와 Tag가 이 프로그램의 마지막 Flash 전송 기록과 일치할 때 그 기록을 표시하며, 이것만으로 전원 차단 후 실제 DSP 계수 보존을 증명하지 않습니다.

7개 모드는 초록·주황 원음 응답 이미지와 제공된 게임·음악·미디어 튜닝 조언을 반영했습니다. Q 0.75에서 권장 게인을 그대로 겹치면 최대 상승이 과도해져, 모드 성격은 유지하면서 계산상 최대 상승을 6dB 이내로 조정했습니다. 정확한 SPL·타깃을 이미지에서 역산한 값은 아니므로 원본 REW와 제품 청음으로 확정해야 합니다.

Windows 크로스 패키징 경로를 제공합니다. Windows 직접 실행·설치·코드 서명·SmartScreen은 별도 검증 대상입니다. 이 환경의 NSIS 생성은 Wine 부재로 실패한 이력이 있으므로 불완전한 설치 EXE를 정상 결과물로 사용하지 않습니다. GitHub 소스는 Python 또는 Node 로컬 서버로 실행할 수 있습니다.
