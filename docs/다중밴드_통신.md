# 웹 EQ의 5·6·10밴드 지원

2026-11-13. PC Chrome/Edge, HTTPS 또는 localhost의 WebHID 기준.
소비자 화면은 AZLA 로고, 연결 상태, 실제 밴드 수만 표시한다. 칩·제품명은 표시하지 않는다. 브라우저 자체의 HID 선택창에 표시되는 장치명은 웹에서 변경할 수 없다.

## 근거

- 사용자가 제공한 `AZLA-KT02H20-Web-Reference.zip`: Kt02Session.java, KtCodec.java, HidPipe.java. Android에서 확인한 5밴드 구현을 WebHID로 이식했다. Report ID는 sendReport 첫 인자로 분리하며 10바이트 payload에 중복 삽입하지 않는다.
- 사용자가 제공한 `kt0231h.zip`: bll_config.h의 unCfgReg/st_eq_param_t, apl_config.h의 apl_eq_param_t, bll_config.c의 mUsbHidUserCB, HID descriptor. 실제 6밴드 레지스터와 쓰기 허용 범위를 기준으로 구현했다.
- 기존의 수정하지 않은 WalkPlay SDK: 10밴드 계수/RAM/Flash 경로 유지. 6밴드 주파수 Hz/2 및 Q×1000, gain×10 변환도 대조했다.

검색 목록에는 제공 6밴드 펌웨어 customdefines.h에 명시된 VID 0x31B2도 포함한다. 이 목록은 검색 범위이며 쓰기 권한을 판정하는 근거는 아니다.

공유 Report ID만으로 기기를 판정하지 않는다. 보고서 크기를 확인하고 읽기 응답을 검증한 뒤에만 쓰기를 허용한다. 10바이트 인터페이스는 protocol 워드로 분기한다. protocol 0x300은 chip 문자열 `0231`도 검증한다. 그 외는 제공 Android와 같이 5개 밴드 전체를 읽고 범위를 검증한다. 36바이트 이상 인터페이스는 기존 10밴드 조회 응답을 확인한다. 알 수 없는 형식/응답은 연결 종료하며 EQ를 쓰지 않는다.

## 통신 차이

5밴드: playback words 0x26~0x2F. 변경 워드만 쓴 후 0x24=1로 RAM commit. 6밴드: playback all_en=0x34, words 0x35~0x40. 펌웨어가 playback 레지스터 쓰기마다 RAM 계수를 갱신한다. 따라서 SDK에 남아 있는 tag(0x16) 또는 RAM commit(0x24) 쓰기를 6밴드에 전송하지 않는다. 제공 펌웨어는 해당 주소 쓰기를 거부한다. 마이크/출력 게인/펌웨어 영역은 쓰지 않는다.

양쪽 모두 첫 워드는 상위16비트 Hz/2, 하위16비트 signed gain×10이다. 둘째 워드는 Q×1000, filter bits16~18, enable bit19이며 그 외 비트를 보존한다. 주파수는 2 Hz 단위, 게인 ±12 dB, Q 0.1~16.0을 지원한다. 10밴드 기존 범위와 기본 프리셋은 유지한다. 화면 필터와 KT wire enum은 명시적으로 변환한다.

5/6밴드 쓰기는 사전 원본 비교 → 직렬 ACK 확인 → RAM 반영 → 전체 readback 비교 순서다. 중간 실패 시 가능한 경우 원본 복구를 시도하되, 확인 여부와 무관하게 재연결을 요구한다. 시간 초과 뒤 응답이 다음 요청에 섞이지 않도록 해당 통신 세션을 폐기한다.

EQ OFF는 5밴드 per-band enable, 6밴드 per-band enable 및 all_en을 사용한다. 10밴드는 원본 SDK에 별도 bypass 명령이 없어 0 dB PEAK 계수로 RAM을 우회하고 편집값은 유지한다. OFF 상태에서 EQ 적용을 누르면 그 우회 설정을 기기에 저장한다.

## 저장과 읽기

슬라이더/프리셋/ON·OFF/초기화는 RAM 전용이며 Flash 명령을 보내지 않는다. 사운드 생성/변경사항 적용은 브라우저 목록 전용이다. EQ 적용만 Flash 저장을 요청한다.

5/6밴드 Flash payload는 `00 00 00 00 53 00 00 00 00 00`. 5밴드 Android는 ACK를 기다리지 않고, 6밴드 펌웨어는 저장 후 reset한다. 전송 성공을 영구 저장 검증으로 표시하지 않는다. `persistenceVerified:false`, 재연결 필요를 기록하고, 소비자에게 다시 연결해 확인하도록 안내한다. 재연결하면 전체 설정을 다시 읽고 마지막 저장 요청값과 일치하는지 별도로 비교한다. 이 비교 자체가 물리적 전원 재연결을 증명하는 것은 아니다.

5/6밴드 저장 EQ 보기는 연결 시 읽은 전체값을 표시한다. 10밴드는 전체값 읽기가 없어 이 프로그램의 마지막 전송 기록만 표시하며 다른 프로그램의 변경을 읽었다고 주장하지 않는다. 다른 밴드 수의 사운드는 목록에서 섞지 않고 저장은 유지한다.

5/6밴드 기본 모드는 연결 시 읽은 중심 주파수를 사용한다. 프리셋 게인은 기존 10밴드 설계의 로그 주파수별 게인 보간으로 옮긴 시작값이며, 같은 합성 응답이나 실제 음향 성능을 보장하는 측정 보정값은 아니다.

## 검증과 제한

`npm test`: 실제 수정하지 않은 10밴드 SDK 검증 + 5/6밴드 패킷, 음수 게인, 원본 비트 보존, 식별 실패, RAM/Flash 분리, 응답 거부/timeout/Flash 전송 실패.
`python tests/browser_multi.py`: WebHID만 모의한 Chromium에서 5/6/10 자동 UI, 실제 SDK 로드, 실시간 미리듣기, ON/OFF, 사운드 생성, 명시적 저장, 5/6 재연결 readback, 제품·칩명 미표시, 데스크톱 크기별 적용 버튼 배치.

이 작업 환경에는 실제 DAC가 없으므로 웹에서의 실기기 연결·청취·전원 재연결 보존 확인은 아직 수행하지 않았다. Android 실기기 확인은 사용자가 제공한 결과다. 오래된 browser_* 테스트의 연결 전 편집 가능 전제는 이번 연결 안내 UX와 다르며 신규 다중밴드 브라우저 시나리오로 검증한다.
