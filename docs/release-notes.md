## 제공 조사 자료 A·E·F·H 적용

- FPS: 인벤 공개 10밴드 값. 보컬: ProMedia Vocal Clarity. 밸런스: ProMedia Loudness. 영화: Reev Immersive.
- 원문 주파수를 사용하며 기존 PEAK·Q 1.4와 수동 ±12 dB 범위를 유지합니다. 기본 모드와 이전 저장 기록은 변경하지 않습니다.
- 합성 +6 dB 보류·확인창은 사용하지 않습니다. 공개 소프트웨어의 리미터·프리앰프는 구현하지 않으며 상시 볼륨 안내는 유지합니다.
- [선택 이유·주파수·게인·한계](조사자료_모드_적용.md)에 기록했습니다. FPS는 밴드별 +12 dB, 합성 예상 최대 약 +17.7 dB로 이전 +5 dB 시험과 다른 조건입니다. 실제 기기 청음·측정은 별도로 확인해야 합니다.

## 밴드별 기준 재계산과 합성 게인 보류 제거

- 합성 +6 dB 조건에 따른 미리듣기 보류·추가 확인창을 제거했습니다. 합성 응답은 정보로만 표시합니다.
- 사용자의 각 밴드 +5 dB 시험 결과를 참고해 용도별 기본 모드의 가장 높은 밴드를 +5 dB로 맞췄습니다. 모든 밴드를 +5 dB로 만드는 것이 아니며 음색 비율을 유지합니다. 수동 조절 범위는 기존 ±12 dB입니다.
- FPS는 제공 이미지의 50%, 보컬은 이전 값의 1.25배, 밸런스는 5/3배, 영화는 10/9배를 0.1 dB 단위로 반올림했습니다. PEAK·Q 1.4를 유지합니다.
- DAC 출력·볼륨 주의 문구는 화면에 상시 표시합니다. 실제 클리핑이 발생하지 않는다는 보증이나 자동 출력 보정은 아닙니다.
- 미리듣기는 RAM 전송만 수행하며 기기에 저장을 눌렀을 때만 Flash를 기록합니다. 저장된 설정 기록은 변경하지 않습니다.
- [전체 값과 기준](밴드별_모드_설정.md), `preset-response-audit.json` 및 `preset-response-curves.csv`에 현재 계산값을 기록했습니다.

## FPS 참고 설정 비례 조정

- 사용자 제공 이미지의 게인 비율에 약 46.49%를 적용하고 0.1 dB 단위로 반올림했습니다.
- 주파수는 31·62·125·250·500·1000·2000·4000·8000·16000 Hz, PEAK·Q 1.4입니다. 이미지에 없는 16 kHz는 0 dB로 유지합니다.
- SDK 합성·누적 최대 약 +5.96 dB로 기존 +6 dB 안내 기준 아래에 두었습니다. 같은 비율의 다음 반올림 단계는 약 +6.06 dB로 기준을 넘습니다.
- 기존 경고 기준과 확인 절차는 유지하며 실제 클리핑이 없는 출력을 보증하는 값은 아닙니다. 다른 모드는 변경하지 않았습니다.
- [원본 값·비율·검증](FPS_비율_조정.md), `preset-response-audit.json`, `preset-response-curves.csv`에 기록했습니다.

## 저장된 설정 불러오기

- 왼쪽 항목 이름을 **저장된 설정**으로 변경했습니다.
- 조절 중인 미리듣기 값과 분리하여 이 프로그램에서 마지막으로 명시적으로 저장한 설정을 불러옵니다. 미리듣기로 변경된 기기 상태가 저장 기록을 덮어쓰지 않습니다.
- 저장 기록이 없으면 안내만 표시하며 기본 모드를 저장된 설정으로 대신 표시하지 않습니다. 다른 장치 식별 정보의 기록은 연결된 기기에 불러오지 않습니다.
- 연결 중 불러온 값은 기존 미리듣기로 반영하고, **기기에 저장**을 눌러야 다시 저장합니다. 새로고침 후에도 같은 브라우저의 마지막 저장 기록을 불러올 수 있습니다.
- 제조사 SDK는 기기의 10밴드 전체를 읽는 기능을 제공하지 않습니다. 이 기능의 값은 앱의 마지막 저장 기록을 기준으로 합니다.
- `tests/browser_saved_settings.py`에서 실제 SDK와 모의 HID로 저장·미리듣기·복원·재실행·장치 불일치·불러오기 중 Flash 미기록을 확인합니다.

## RAM 미리듣기와 Flash 저장 분리

- 연결 후 슬라이더·숫자·그래프·모드를 바꾸면 RAM에 임시 반영합니다. Flash 저장은 **기기에 저장**을 누를 때만 실행합니다. 기존 프리셋 값과 필터는 유지합니다.
- 빠른 연속 조절은 최신 값으로 모아 한 번에 하나씩 전송합니다. 첫 반영은 전체 10밴드, 이후는 변경된 밴드와 원본 SDK의 RAM 반영 명령을 사용합니다. SDK 원본과 USB 명령 간격은 유지합니다.
- 저장 시 대기 중인 편집값을 취소하고 진행 중인 RAM 전송이 끝난 뒤 버튼을 누른 시점의 10밴드를 보내 Flash를 1회 기록합니다.
- 예상 최대 상승 +6 dB 초과 시 자동 미리듣기를 보류하고 **볼륨 확인 후 미리듣기**를 표시합니다. 확인은 해당 EQ 값의 미리듣기만 허용하며 저장은 별도입니다. 이 수치는 앱 안내 기준으로 실제 클리핑 한계는 아닙니다.
- 현재 상태에서 RAM 미리듣기와 마지막 Flash 전송 기록을 구분합니다. 연결·화면 종료·새로고침은 EQ를 자동 저장하지 않습니다.
- 단위 검증, 수정하지 않은 SDK와 모의 HID, Chromium 브라우저에서 전송 순서·큰 증폭 확인·오류·저장 버튼 노출을 검증합니다. 실제 DAC에서 반응 속도·음향 변화·전원 재연결 후 상태는 별도 확인이 필요합니다.

- 공개 음향 자료와 첨부 제안서를 검토해 FPS·보컬·밸런스·영화를 자체 재설계했습니다. FPS 저역 감쇄는 유지하면서 효과음 대역을 더 강조하고, 보컬의 존재감·밸런스의 저고역·영화의 깊은 저음을 강화했습니다. SDK 합성·누적 최대 상승은 +5.5 dB 이하입니다. [근거와 정확한 값](사운드_라이브러리_튜닝.md)을 기록했습니다. 기본 프리셋은 클리핑 안내 기준 아래로 조정했으며, 수동 조절 시의 기존 안내와 기기 적용 기능은 유지합니다.
- 우측 사용자 저장, 저장 창, 가져오기·내보내기를 제거했습니다. 새 버전 첫 실행 시 v1~v4 사용자 저장 키를 삭제하며 매 실행 기본 모드로 시작합니다.
- 장치 문제 확인을 위한 설정의 **진단 기록 저장**은 유지합니다.

**Windows 실행 방법**

1. Assets에서 `AZLA-Equalizer-Windows.zip`을 받습니다.
2. ZIP 전체를 압축 해제하고 `AZLA Equalizer.exe`를 실행합니다. EXE만 따로 옮기지 마세요.
3. 기기 연결 → 본인의 AZLA DAC 선택 → 볼륨 낮추기 → 사운드 모드 선택·조절하며 미리듣기 → 기기에 저장을 누릅니다.

Python 또는 Node.js를 따로 설치할 필요가 없습니다.

기기에 저장은 수정하지 않은 원본 SDK의 10밴드/RAM/Flash 명령을 사용합니다. 실제 Flash 명령은 `[1,1,0]` 3바이트이며, SDK 원본 해시는 유지했습니다.

43개 소프트웨어 검증과 Chromium의 원본 SDK + 모의 HID Tag 읽기·현재 상태·Flash 전송 검증은 통과했습니다. 새 버전의 실제 DAC 연결, Tag 응답, 음향 응답 및 전원 차단 후 설정 보존은 별도 실기 검증 대상입니다. 완료 표시는 Flash 저장 명령 전송 완료를 뜻합니다.

이 빌드는 코드 서명되지 않은 검토용이며 양산 출하 검증 완료본이 아닙니다.

FPS는 PUBG·VALORANT의 공개 게임 음향 분석을 참고해 125 Hz를 보강하고 9번째 대역을 8 kHz에서 6 kHz로 변경했습니다. 실제 게임 녹음으로 확정한 최적값은 아니며, 자세한 근거는 docs/FPS_게임_음향_검토.md에 기록했습니다.

FPS의 32·63 Hz를 −4 dB, 125 Hz를 +3 dB, 500 Hz를 −2 dB, 1 kHz를 +3 dB로 조정했습니다. PEAK·Q 1.4를 유지하고 SDK 합성 최대 약 +5.48 dB를 검증했습니다.
