AZLA CB5100 / CB5100PRO EQ Test Studio v1.4 — 10밴드 개발·측정용
================================================================

[이번 버전에서 바뀐 점]
1. 제조사 확인에 따라 CB 유형의 EQ를 8개 → 10개 밴드로 확장했습니다.
   - 칩 유형: CB 그대로 사용 (CB1300D로 전환하지 않음)
   - 10개 EQ 패킷(밴드 인덱스 0~9) + RAM 메모리 반영 명령 1개
   - Flash 저장에서도 10개를 다시 전송한 후 Flash 쓰기 명령을 호출
   - 패킷 전송 순서/개수/밴드 인덱스를 확인하고, 실패하면 성공 메시지를 표시하지 않음
2. 제조사 WALK PLAY 10밴드 화면의 주파수/Q를 기본값으로 사용합니다.
   주파수 Hz: 50 / 125 / 250 / 500 / 1000 / 2000 / 4000 / 8000 / 11000 / 16000
   Q: 0.65 / 0.75 / 0.60 / 0.75 / 0.75 / 0.75 / 1.20 / 0.75 / 0.75 / 0.75
   새 사용자 설정과 FLAT의 기본 게인은 전부 0dB입니다.
   주의: 이 값은 제조사 화면의 예시 기본값으로, 칩에 고정된 주파수가 아닙니다.
3. FPS/음악/FLAT/사용자 프리셋을 모두 10밴드로 변경했습니다.
   FPS는 300Hz +8dB / 3200Hz +9dB의 실험용 강한 부스트를 유지했습니다.
4. 기존 8밴드 프리셋을 보존하면서 10밴드로 변환합니다.
   - 기존 1~8번의 주파수/Q/게인/필터는 그대로 유지합니다.
   - 9~10번을 11000/16000Hz, Q=0.75, PEAK, 게인 0dB로 추가합니다.
   - 새 10밴드 기본값이 필요하면 사운드 모드에서 FLAT을 선택하세요.
   - 예전 8밴드 JSON 내보내기 파일도 [가져오기]로 읽을 수 있습니다.
5. SDK가 만든 정수 계수로 전체 10밴드 예상 응답을 계산합니다.
6. 예상 필터 중첩 최대 게인값을 보여주고 +6dB 초과 시 클리핑 위험을 표시합니다.
   자동 헤드룸/자동 전체 출력 감쇄는 적용하지 않습니다.
7. [전송 로그 저장]은 최근 HID 전송 데이터와 10밴드 패킷 검증 결과를 JSON으로 다운로드합니다.
8. RAM/Flash 동작은 원본 WALK PLAY SDK v1.0.0 파일을 변경하지 않고 사용합니다.

[실행]
1. 압축 파일 안의 CB5100_EQ_Test_Studio_v1.4 폴더를 완전히 압축 해제합니다.
2. Windows에 Python 3가 설치돼 있어야 합니다.
3. 이전 v1.3의 서버 창(8768 포트)을 먼저 닫습니다. 구 프로그램이 켜져 있으면
   같은 포트에서 v1.4를 실행할 수 없습니다.
4. start_windows.bat 를 실행합니다.
5. Chrome 또는 Edge에서 http://localhost:8768 주소로 접속합니다.
   이전 화면이 보이면 Ctrl+Shift+R을 눌러 새로 고칩니다. 화면 상단 v1.4 확인.
6. CB5100PRO USB DAC 연결 → EQ 조정 → [임시 적용 (RAM)] 으로 테스트하세요.
7. 청음/측정 확인 뒤 필요한 설정에만 [Flash에 저장]을 실행하세요.

[프리셋 호환성]
- v1.3과 동일한 http://localhost:8768 주소로 실행하면 기존 localStorage 설정을
  자동으로 10밴드 형식으로 변환합니다.
- 다른 PC/브라우저/포트 사용 시 구 버전에서 JSON으로 내보낸 파일을 가져오세요.
- 프리셋 파일은 현재 설정과 저장한 사용자 프리셋의 JSON이며, 장치 Flash에
  여러 프리셋을 동시에 저장하는 기능은 아닙니다.

[REW 비교]
- EQ OFF와 EQ ON 측정 데이터를 TXT/CSV로 각각 저장한 다음 두 파일을 불러옵니다.
- 10개 밴드 중심 주파수별 SDK 예측값 / 실측 변화량 / 차이를 표시합니다.
- 동일한 장착/측정/볼륨 조건의 파일을 사용하세요.
- 파일은 브라우저에서만 읽고 외부 서버로 업로드하지 않습니다.

[주요 기술 사양 및 안전]
- SDK 칩 타입: CB / HID Report ID: 75 (0x4B).
- EQ 패킷: 36byte x 10개. 메모리 반영 명령: 7byte x 1개.
- 명령 간격: 130ms, HID sendReport 완료를 기다린 뒤 다음 명령 전송.
- 플래시 저장 명령은 별도이며, 저장 전에 EQ 10밴드를 모두 다시 전송합니다.
- 기본 그래프 기준 샘플링 주파수: 원본 SDK의 CB PEAK 계산 기준 96kHz.
  실제 DSP 내부의 실행 레이트/DRC 상태를 확인한 값은 아닙니다.
- 게인 입력 범위 ±12dB, Q 범위 0.5~5.0은 프로그램 설정 범위이지
  CB5100PRO의 제조사 공식 최대 허용 사양이라는 의미는 아닙니다.
- PEAK는 Q/게인/주파수 모두 사용합니다.
- LOW SHELF는 SDK 원본에서 Q를 계산에 적용하지 않습니다.
- HIGH SHELF는 SDK 원본 계수 구현의 실기 검증이 필요해 실험용입니다.
- LOW PASS/HIGH PASS는 게인 0dB로 설정해도 응답이 평탄해지지 않습니다.
- 자동 헤드룸 보정, DRC 제어, DAC 전역 출력 게인 setDacOffset 호출 없음.
- 예상 그래프는 필터 계수의 수학적 응답이지 실제 이어 시뮬레이터 결과는 아닙니다.
- 높은 양의 게인을 동시에 사용하면 원음/출력에 클리핑과 왜곡이 발생할 수 있습니다.
- Flash에는 현재 1개 EQ 설정을 기록합니다. 기기 내 프리셋 개수 확장은 검증되지 않았습니다.
- 기존 Flash 저장 동작은 사용자 보드에서 확인된 바 있지만,
  이 버전의 10밴드 전체 쓰기와 전원 재연결 보존은 실물 재확인 전까지 미검증입니다.

[검증]
- 원본 SDK UMD 파일을 수정하지 않고 포함했습니다.
- CB 타입에 제조사 10밴드를 전달해 36byte 패킷 10개 + 갱신 7byte를 생성함을 확인.
- Node 가상 DOM + 모의 HID 장치에서 10밴드 RAM 적용 및 Flash 쓰기 명령 전송 통과.
- 기존 8밴드 로컬 저장값을 10밴드로 변환하는 테스트 통과.
- 실제 CB5100PRO 보드와의 통신/이어 시뮬레이터 주파수 응답은 이 실행 환경에서
  테스트할 수 없어 결과를 보증하지 않습니다.
